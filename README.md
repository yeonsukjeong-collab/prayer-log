# 자카르타 목장

목장 모임의 릴레이 기도(대표기도문)와 기도제목을 함께 작성하고 관리하는 웹 앱(PWA)입니다.

- **프론트엔드**: React + Vite + TypeScript + Tailwind CSS (PWA)
- **백엔드**: Node.js + Express + TypeScript
- **DB**: PostgreSQL (Prisma ORM) — Render의 기존 Postgres 인스턴스 사용
- **로그인**: 정해진 목장원 명단(이름) + 목장 공유 암호 (계정 가입 없음, 명단에 없는 이름은 로그인 불가)
- **배포**: Render Web Service 1개로 프론트/백엔드 통합 배포

> `client/package.json`의 `xlsx`는 npm 레지스트리가 아니라 `https://cdn.sheetjs.com/...` 주소로 설치되어 있습니다. npm 레지스트리에 올라온 최신 버전(0.18.5)에는 보안 패치가 반영되지 않아, SheetJS가 공식적으로 안내하는 CDN 배포판을 사용했습니다. `npm install`만으로 그대로 동작합니다.

## 1. 로컬 개발 환경 설정

```bash
npm run install:all
```

`server/.env.example`을 `server/.env`로 복사 후 값 채우기:

```
DATABASE_URL=postgresql://...   # Render Postgres의 External Database URL
ACCESS_PASSWORD=...             # 목장원 전체가 사용할 공유 암호
ANTHROPIC_API_KEY=...           # 성경퀴즈용 Claude API 키 (비워두면 성경퀴즈만 비활성)
LEADER_PASSWORD=...             # 목자(정연석) 전용 암호 (비워두면 공유 암호 사용)
JWT_SECRET=...                  # openssl rand -hex 32 로 생성
CLIENT_URL=http://localhost:5173
```

DB 스키마 생성 (최초 1회, 로컬에서 Render Postgres에 직접 마이그레이션 적용):

```bash
npm run prisma:migrate:dev
```

목장원 명단 시딩 (최초 1회, 또는 명단이 바뀔 때):

```bash
npm run prisma:seed --prefix server
```

목장원을 추가·변경하려면 `server/prisma/seed.ts`의 `MEMBERS` 배열과 `client/src/constants.ts`의 `MEMBER_NAMES` 배열을 함께 수정한 뒤 위 시드 명령을 다시 실행하세요.

개발 서버 실행 (프론트 5173, 백엔드 3000, `/api` 프록시 설정됨):

```bash
npm run dev
```

## 2. 로그인 방식

목장원은 접속 후 미리 정해진 명단에서 **이름을 선택**하고 **공유 암호**(목자가 정해서 알려준 암호)를 입력해 들어옵니다.

- 명단에 없는 이름이거나 암호가 틀리면 로그인할 수 없습니다.
- 로그인하면 그 이름으로 작성한 글만 본인이 수정·삭제할 수 있습니다 (목자는 예외 — 아래 참고).
- 계정 가입이나 비밀번호 찾기 절차가 없어 관리 부담이 없습니다.
- 암호는 `ACCESS_PASSWORD` 환경변수로 관리하며, 바꾸고 싶으면 이 값만 변경하면 됩니다 (기존에 로그인된 브라우저는 세션이 끊길 때까지 유지됨).

### 작성자 선택

기도제목을 등록할 때 누구나 풀다운 메뉴에서 **작성자(누구의 기도제목인지)**를 선택할 수 있습니다. 기본값은 로그인한 본인 이름이며, 전화·문자 등으로 받은 기도제목을 대신 입력할 때는 다른 목장원 이름을 선택하면 됩니다.

수정·삭제는 여전히 실제 작성자 본인만 할 수 있습니다. 예외로, 시드 데이터 기준 **정연석**이 목자(싸이트 관리자)로 지정되어 있어(`server/prisma/seed.ts`의 `isLeader: true`) 다른 사람이 작성한 기도제목·릴레이 기도문도 관리(수정·삭제)할 수 있습니다.

### 웹관리자

**정연석**, **김선경**이 웹관리자로 지정되어 있습니다(`server/prisma/seed.ts`의 `isAdmin: true`). 웹관리자로 로그인하면 "여러 명 기도제목 한번에 붙여넣기" 기능이 보입니다 — 일반 목장원에게는 이 기능이 표시되지 않습니다.

### 성경퀴즈 탭

예전 `bible_quiz_web`(Flask) 앱을 옮겨 온 탭입니다. 출제 범위·난이도·문제 수·참여자를 정하면 Claude(`claude-opus-5-5`)가 객관식 문제를 만들고, 문제 → 정답 확인(맞힌 사람 선택) → 최종 순위 순서로 진행합니다.

- 서버의 `POST /api/bible-quiz`(`server/src/routes/bibleQuiz.ts`)가 Anthropic SDK로 Claude를 호출합니다. 원래 앱은 Google Gemini를 썼지만 Claude로 바꿨습니다. 구조화 출력(`zodOutputFormat`)으로 정해진 JSON 형식으로만 답하게 하고, Claude가 안전 정책으로 거절하면 다른 모델로 자동으로 다시 시도합니다(server-side fallback). API 키는 서버 환경변수 `ANTHROPIC_API_KEY`에만 두고 브라우저에는 보내지 않습니다. 키가 없으면 성경퀴즈만 "설정되지 않음"으로 표시되고 앱의 다른 기능은 그대로 동작합니다.
- 난이도는 쉬움·보통·어려움 세 가지 키로만 받고 프롬프트 문구는 서버에서 정합니다. Claude가 만든 문제 중 보기가 4개가 아니거나 정답이 보기에 없는 문제는 빼고 보여줍니다.
- 두 가지 방식이 있습니다.
  - **다 함께 풀기**(`client/src/components/quiz/LiveQuiz.tsx`, `server/src/routes/liveQuiz.ts`): 누군가 퀴즈를 열면 목장원들이 각자 휴대폰으로 참가해 같은 문제를 동시에 풉니다. 각자 고른 답을 서버가 모아 점수를 매기고, 정답 공개 후 맞힌 사람과 순위를 모두에게 보여줍니다. 퀴즈를 연 사람이 진행자(시작·정답 공개·다음 문제·끝내기)이고 목자도 언제든 진행할 수 있습니다. 제한 시간은 없고, 정답 공개 전까지는 답을 바꿀 수 있어 마지막에 고른 답을 인정하며, 점수가 같으면 정답을 더 빨리 고른(마지막으로 바꾼 시각 기준) 사람이 앞섭니다.
  - **매번 다른 문제**: 출제한 문제는 `prayer_log_quiz_history` 테이블에 범위별로 최근 300개까지 남깁니다. 같은 범위로 다시 출제할 때 최근 80개를 프롬프트에 넣어 피하게 합니다. 범위가 책 한 권이면 매번 무작위 장 구간(약 1/3)을 고르고, 문제 유형(인물·장소·숫자 등)도 무작위로 4가지를 골라 줍니다.
    - 진행 중인 게임은 목장 전체에 하나뿐이고 **서버 메모리에만** 둡니다(DB 저장 없음). 서버가 다시 시작되면(배포·Render 슬립) 진행 중인 게임은 사라집니다. 2시간 동안 진행이 없으면 버려진 게임으로 보고 새 게임을 열 수 있습니다.
    - 화면은 1.5초마다 `GET /api/live-quiz/state`로 상태를 받아 갑니다. 정답은 공개 단계 전에는 화면으로 보내지 않습니다.
  - **한 화면에서 풀기**(`client/src/components/quiz/LocalQuiz.tsx`): 예전 방식 그대로 한 기기를 함께 보며 풀고, 맞힌 사람을 골라 점수를 매깁니다. 점수는 브라우저에서만 계산합니다.

## 3. Render 배포

이 저장소를 GitHub에 올린 뒤 Render 대시보드에서 "New Web Service"로 연결하거나, 저장소 루트의 `render.yaml`(Blueprint)을 이용해 한 번에 생성할 수 있습니다.

Render 서비스에 아래 환경변수를 설정하세요 (기존 Postgres 인스턴스의 접속 정보 사용):

- `DATABASE_URL` — 기존 Render Postgres의 **External Database URL** (Internal Database URL은 웹 서비스와 DB가 같은 리전에 있을 때만 동작합니다. 웹 서비스를 DB와 같은 리전으로 만들었다면 Internal URL을 써도 됩니다.)
- `ACCESS_PASSWORD` — 목장원 전체가 사용할 공유 암호
- `LEADER_PASSWORD` — 목자(정연석) 전용 암호. 설정하면 목자는 공유 암호 대신 이 암호로만 로그인합니다.
- `ANTHROPIC_API_KEY` — 성경퀴즈용 Claude API 키 ([platform.claude.com](https://platform.claude.com)에서 발급)
- `GOOGLE_DRIVE_SCRIPT_URL`, `GOOGLE_DRIVE_SCRIPT_SECRET` — 사진을 구글 드라이브에 저장하는 앱스 스크립트 주소와 비밀 키 (아래 "사진을 구글 드라이브에 저장하기" 참고). 비워두면 사진을 예전처럼 DB에 저장합니다.
- `JWT_SECRET` (Blueprint 사용 시 자동 생성됨)
- `CLIENT_URL` — 배포된 앱의 URL (예: `https://prayer-log.onrender.com`)

Build Command:
```
cd client && npm install --include=dev && npm run build && cd ../server && npm install --include=dev && npm run build && npx prisma migrate deploy
```

Start Command:
```
node server/dist/index.js
```

> DB 테이블은 다른 서비스와 충돌하지 않도록 `prayer_log_` 접두사를 붙여 생성됩니다 (`prayer_log_members`, `prayer_log_prayer_requests`, `prayer_log_prayer_texts`, `prayer_log_photos`, `prayer_log_photo_comments`, `prayer_log_benediction`, `prayer_log_pastor_prayers`). 기존에 사용 중인 Postgres에 다른 앱의 테이블이 있어도 안전하게 함께 쓸 수 있습니다.
>
> 브라우저에서 업로드 전 원본 크기와 무관하게 사진을 최대 1MB(1장당)로 자동 리사이즈·압축합니다 (`client/src/utils/image.ts`).

### 사진을 구글 드라이브에 저장하기

DB 용량을 아끼려고 사진은 정연석 목자의 구글 드라이브("자카르타 목장 사진" 폴더)에 저장하고, DB에는 드라이브 파일 ID(`driveFileId`)만 남깁니다. 서버는 그 계정으로 배포한 앱스 스크립트(`google-apps-script/photoDrive.gs`)에 사진을 보내 저장합니다.

- 드라이브의 사진은 "링크가 있는 사람은 보기 가능"으로 공유되고, 앱은 서버의 `/api/photos/:id/image`를 거쳐 사진을 보여줍니다(서버가 `drive.google.com/thumbnail`에서 받아 전달). 브라우저가 드라이브 주소를 직접 열면 PC에서 구글 로그인 상태에 따라 사진이 막히는 일이 있어서입니다.
- 앱에서 사진을 지우면 드라이브의 파일은 휴지통으로 옮겨집니다.
- 예전에 DB에 저장된 사진은 서버가 켜질 때마다 아직 옮기지 않은 것을 하나씩 드라이브에 복사합니다(`copyOldPhotosToDrive`). DB의 이미지 데이터는 지우지 않고 남겨둡니다.
- 환경변수를 비워두면 예전처럼 사진을 DB에 저장합니다.

설정 순서 (사진을 저장할 구글 계정으로 로그인한 상태에서):

1. [script.google.com](https://script.google.com)에서 **새 프로젝트**를 만들고, `Code.gs` 내용을 지운 뒤 `google-apps-script/photoDrive.gs` 내용을 붙여 넣고 저장합니다.
2. 위쪽 함수 목록에서 `setup`을 고르고 **실행**합니다. 권한 요청이 나오면 계정을 고르고, "Google에서 확인하지 않은 앱" 화면에서는 **고급 → (프로젝트 이름)(으)로 이동(안전하지 않음) → 허용**을 누릅니다.
3. 실행 로그에 나온 `GOOGLE_DRIVE_SCRIPT_SECRET = ...` 값을 복사해 둡니다.
4. **배포 → 새 배포 → 유형: 웹 앱**을 고르고, "다음 사용자 인증 정보로 실행: **나**", "액세스 권한이 있는 사용자: **모든 사용자**"로 배포합니다. 나온 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사합니다.
5. Render 서비스의 Environment에 `GOOGLE_DRIVE_SCRIPT_URL`(4번 URL)과 `GOOGLE_DRIVE_SCRIPT_SECRET`(3번 값)을 넣고 저장합니다. 서버가 다시 시작되면서 예전 사진 복사가 시작됩니다.

스크립트 코드를 고친 뒤에는 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전**으로 다시 배포해야 반영됩니다(URL은 그대로 유지됩니다).

## 4. PWA 아이콘

파비콘과 홈 화면 아이콘(`favicon.png`, `pwa-192x192.png`, `pwa-512x512.png`)은 기도하는 사람 모양으로 되어 있습니다. 다른 아이콘으로 바꾸려면 `client/public/`의 해당 파일들을 교체하세요.

## 주요 기능

- 정해진 명단 + 공유 암호로 로그인 (명단에 없는 이름은 로그인 불가)
- 기도제목 등록 시 작성자를 풀다운 메뉴에서 선택 가능 (대신 입력), 표시는 작성자 이름 · 날짜(요일)
- (웹관리자 전용) `(이름)` + `- 항목` 형식으로 여러 명의 기도제목을 붙여넣으면 사람별로 자동 구분해서, 한 사람당 기도제목 1건으로 일괄 등록
- 기도제목·릴레이 기도 목록은 목원별·기간별(최근 1주/2주/1달/전체/날짜 직접 선택)로 서버에서 조건에 맞게 조회 (기본은 전체 목원·최근 1주간만 불러옴, 필터를 바꾸면 그 조건으로 다시 조회)
- 기도제목 카드 상단에 이름·날짜(요일)를 굵은 파란 글씨로 표시, 하이픈 항목은 들여쓴 글머리 기호 목록으로 표시
- 기도제목·릴레이 기도 목록 확인 (실제 작성자 본인만 수정·삭제 가능, 목자는 전체 관리 가능)
- 카드 상단 우측의 "수정" 버튼으로 내용·날짜 수정 + 응답 여부/응답 내용을 함께 편집
- 릴레이 기도 작성 시에도 작성자를 풀다운 메뉴에서 선택 가능, 카드 상단에 이름·날짜(요일) 굵은 파란 글씨로 표시
- 기도제목·릴레이 기도 모두 등록/수정 시 날짜를 직접 선택 가능 (기본값은 오늘)
- 기도제목·릴레이 기도 모두 목원·기간 필터 옆 "📊 다운로드" 버튼으로 현재 필터 조건(전체 목원 또는 특정 목원, 선택한 기간)에 맞는 목록을 .xlsx 파일로 내려받을 수 있습니다. 엑셀 생성 라이브러리(SheetJS)는 버튼을 누를 때만 불러와서 평소 로딩 속도에는 영향이 없습니다.
- 화면 글자 크기 조절 아이콘 (브라우저에 저장됨)
- **사진** 탭: 사진 촬영/업로드, 날짜별로 묶은 썸네일 그리드, 클릭 시 원본 보기. 목록에는 작은 썸네일만 전달하고 원본은 클릭 시에만 불러와 로딩을 가볍게 유지
  - 정렬 기준은 업로드한 시각이 아니라 **사진이 실제로 찍힌 날짜**입니다. 사진 파일의 EXIF 촬영 날짜를 자동으로 읽어오고(`client/src/utils/exif.ts`), 정보가 없는 사진만 업로드 시 선택한 날짜를 사용합니다.
  - 원본 사진을 볼 때 "다운로드" 버튼으로 기기에 저장할 수 있습니다.
  - "사진 촬영" 버튼은 모바일에서는 기기의 카메라 앱을 열고, 컴퓨터(PC)에서는 웹캠 미리보기 화면을 띄워 바로 촬영할 수 있습니다 (`getUserMedia` 사용, HTTPS 또는 localhost에서만 동작).
  - 사진 확대 화면에서 댓글을 달 수 있습니다. 삭제는 댓글 작성자 본인 또는 목자만 가능합니다.
  - 댓글이 달린 사진은 썸네일 우측 하단에 댓글 개수(💬)가 표시됩니다.
- **교회** 탭 (은혜샘물교회):
  - **축도**: 매주 목사님이 예배 말미에 주시는, 매번 동일한 축도문을 목장원 누구나 언제든 볼 수 있습니다. 단일 문서로 존재하며 화면에서는 읽기 전용입니다 — 내용을 바꾸려면 `PUT /api/benediction`(웹관리자·목자 권한 필요, `server/src/routes/benediction.ts`)을 직접 호출해서 갱신해야 합니다.
  - **오늘의 찬양**: 주보(목회 편지) 아래에 매일 한 곡씩 찬양 영상을 보여줍니다. 썸네일을 누르면 앱 안의 작은 화면에서 재생되고, "전체화면" 버튼이나 유튜브 플레이어의 전체화면 버튼으로 크게 볼 수 있습니다.
    - 곡은 `server/src/routes/praise.ts`의 `SONGS` 목록에서 자카르타 날짜 기준으로 하루 한 곡을 고릅니다(모든 목장원이 같은 날 같은 곡). 영상 주소를 따로 적어 두지 않고, 서버가 그날 곡을 유튜브에서 검색해 한 곡짜리 영상(2~8분, 제목에 메들리·모음·"+" 등 없음, 퍼가기 허용)을 찾은 뒤 하루 동안 캐시합니다. 곡을 바꾸려면 `SONGS`만 고치면 됩니다. "다음 곡" 버튼을 누르면 그날 순서에서 다음 곡을 찾아 보여주고, 한 번 찾은 곡은 그날 동안 다시 검색하지 않습니다.
    - 유튜브 검색 화면을 읽는 방식이라 유튜브가 페이지 구조를 바꾸면 동작하지 않을 수 있습니다.
  - **말씀 묵상**: 매일 묵상한 말씀 구절을 기록합니다. 말씀서(66권 목록에서 선택), 장, 시작 절, 끝 절(선택)과 말씀 본문을 입력하면 "야고보서 2장 12절~13절"처럼 표시됩니다(시편은 "편"). 작성자와 날짜는 자동으로 기록됩니다. 목장원 누구나 작성할 수 있고, 수정·삭제는 작성자 본인 또는 목자만 가능합니다.
    - 말씀 본문은 글자를 선택해 굵게·밑줄·글자색(빨강·파랑·노랑·초록, 기본 빨강)을 넣을 수 있습니다. HTML로 저장되며, 화면에 보여줄 때 DOMPurify로 이 서식 외의 HTML은 모두 걸러냅니다(`client/src/utils/richText.ts`).
    - 기도제목·릴레이 기도처럼 목원·기간별로 보고 엑셀로 내려받을 수 있습니다. 기간은 작성 시각 기준이며, 브라우저의 현지 날짜(자정)로 계산합니다. 엑셀에는 서식을 뺀 글자만 들어갑니다.
    - 예전의 "목사님 기도문" 기능은 화면과 API에서 제거했지만, 기존 기도문 보존을 위해 `prayer_log_pastor_prayers` 테이블은 DB에 남겨두었습니다.
  - **주보**: 은혜샘물교회 홈페이지(`www.osmcc.or.kr`)의 주보 게시판을 서버에서 주기적으로 읽어와(`server/src/routes/bulletin.ts`, cheerio로 HTML 파싱, 30분 캐시) 가장 최근 주보의 썸네일·제목을 보여주고, 클릭하면 교회 홈페이지 원본 게시물로 이동합니다. "원본보기" 아래에는 담임목사님의 **목회편지** 페이지 이미지를 함께 보여줘서, 주보 전체를 열지 않아도 목회편지만 바로 읽을 수 있습니다. 교회 홈페이지가 HTML 구조를 바꾸면 파싱이 깨질 수 있습니다 — 그럴 땐 코드 수정이 필요합니다.
    - 목회편지는 매주 주보의 9번째 쪽(갤러리 이미지 중 9번째)에 고정적으로 실리는 템플릿 순서에 의존해서 가져옵니다(`PASTORAL_LETTER_IMAGE_INDEX`). 교회가 주보 쪽 구성을 바꾸면(예: 감사제목이 여러 쪽으로 늘어나는 등) 목회편지 위치가 밀려서 엉뚱한 페이지가 표시될 수 있습니다 — 그럴 땐 `server/src/routes/bulletin.ts`의 `PASTORAL_LETTER_IMAGE_INDEX` 값을 그 주 주보에 맞게 수정해야 합니다. (이전에 OCR로 쪽 제목을 자동 인식하는 방식을 시도했지만, 쪽마다 OCR을 돌리느라 로딩이 너무 느려져서 고정 위치 방식으로 되돌렸습니다.)
